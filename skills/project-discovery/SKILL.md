# Project Discovery

Inspect supplied answers and existing project evidence first. Separate confirmed facts, material assumptions and open decisions.
Ask focused batches about users/outcome/MVP, application/platform, journeys/pages, UI/UX, backend/data, stack constraints, security, tests and delivery only where unanswered and applicable.
Consolidate specialist questions through the primary coordinator. Do not ask about settled choices again or treat silence as an answer. Explain options and tradeoffs; keep required missing decisions pending while drafting independent plans.
Convert answers into observable acceptance criteria, exclusions, dependencies and a bounded plan under docs/. Do not invent business rules, content, roles, prices, providers or credentials. Adapt to the actual language/platform and existing stack.
Read applicable project instructions and preserve unrelated edits. No external provisioning or implementation of material guesses. If native subagents are unavailable, work sequentially and disclose that limitation.
