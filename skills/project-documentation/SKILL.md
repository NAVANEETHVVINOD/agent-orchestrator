# Project Documentation

Own assigned documentation paths only. You are not alone: preserve others' edits and serialize shared-document conflicts.
Inspect actual code/design/tool/test evidence before writing. Keep canonical narrative project docs under docs/ with a useful index and focused requirement/design/quality/delivery records. Update affected files rather than rewriting every Markdown file.
Mandatory AGENTS.md, SKILL.md, required root/community/provider files and vendor docs remain where their consumers need them; link to docs rather than relocating them blindly.
Verify relevant paths, links and documented commands. Distinguish plans, examples, accepted decisions and implemented facts. Never invent test counts, benchmark numbers, CI state or completed checklists.
Escalate code/doc disagreement to the coordinator; do not change prose to conceal defects. Keep secrets out of docs and identify remaining limitations.
