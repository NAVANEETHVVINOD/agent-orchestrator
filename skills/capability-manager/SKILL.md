# Project capability manager

Start with the requested project, acceptance criteria and actual session catalog/tool
schemas. Reuse suitable connected capabilities and existing roles. Identify the concrete
gap before researching tools or generating another skill. Do not install a framework
just because it is popular or listed in a registry.

Read [the acquisition and creation contract](references/capability-lifecycle.md).
Use a scoped capability_researcher or native read-only fallback to compare maintained
primary-source candidates, exact source/artifact versions, licenses, compatibility,
privileges, data destinations, costs, dependencies and evaluation evidence. Include
reuse/direct implementation as alternatives. Separate verified facts from vendor claims.

The coordinator selects from evidence and confirmed constraints. For creation, assign
an owned-file worker/scoped_implementer and load the host's skill-creator/mcp-builder
guidance when available. Otherwise follow the self-contained creation contract here.
Keep generated role instructions bounded; they cannot invent tools, permissions or
independent reviewers. Independently review and test the result before activation.

Adopt only the selected reviewed source/artifact into the authorized scope. Reuse
existing authorization for the same action/target; a recommendation or model score
does not authorize arbitrary installs, account linking, global changes or data uploads.
Prepare a concrete plan/diff first when authority is missing. Never overwrite another
user's same-name role/skill or change permission policy to make an integration work.

Track candidate -> selected -> reviewed -> created/downloaded -> installed ->
configured -> registered/discovered -> connected/authenticated when applicable ->
smoke-tested -> active, or rejected/blocked/rolled back.
Each transition needs actual evidence. Installed files alone cannot pass a live-connection
check. Record exact scope, source revision/digest, test results, update policy and rollback
in the project's docs/. Stop the failing capability, preserve evidence, and continue
independent work after a demonstrated integration failure.
